## 1. 背景と目的

### 1.1 現状

- `src/repack_tool/` に CLI（`cli.py`）・GUI（`gui.py`）・Core（`core.py` 他）が一体で実装。
- エントリは `python -m repack_tool`（CLI）と `python -m repack_tool.gui`（GUI）。
- `pyproject.toml` の配布名も `repack-tool` 単機能が前提。

### 1.2 目的

- 本機能を壊さずに**機能追加に強いスイート構成**へ移行する。
- 第2機能「デジタル保有資産一覧出力」（指定フォルダを読み取り、サブフォルダ単位の保管ファイル＝主にzipを一覧出力）を同じ土台に載せる。
- GUIは **TOP画面 → 各機能画面** の遷移モデルに統一する。

### 1.3 非目的（今回やらないこと）

- repack機能自体の仕様変更（分類・命名・終了コード等は現行維持）。
- Web化・常駐化・DB導入。出力はファイル（CSV/HTML等）に留める。
- インストーラ化・自動更新（必要なら別案件）。
- 資産一覧の**更新系操作**（削除・移動・リネーム）と**重複検出**（`--with-hash` は将来の重複検出の材料提供まで・Q29-15）。
- `--no-empty`（実体のあるフォルダのみ出力）と `--rollup`（配下のみの集約表）は拡張候補として保留（Q29-13・12章）。

### 6.1 機能概要【確定: Q5/Q6/Q7/Q9/Q13'/Q15/Q19'/Q20'/Q21'/Q29=C】

- 入力：起点フォルダ（例：`D:\資産`）。**読み取り専用**（更新系操作は非目的・1.3）。
- 集約単位：**起点からの全階層のフォルダ（深さ非固定）を1フォルダ1行**とする（Q29=C）。階層数を固定しないため、将来 下位に分類フォルダが増えても同じルールで動作する。
  `--no-recursive` 指定時のみ「起点直下のフォルダのみ1行」（旧Q19=A）に切替える。
- 各行の統計：**直下**（そのフォルダ直下のファイル）と**配下**（サブツリー全体の再帰集計）の両方を持つ。
  - リーフ判定：`ファイル数(直下) == ファイル数(配下) かつ > 0`
  - 前提違反検出：`ファイル数(直下) != ファイル数(配下)`（＝リーフ以外に実体が存在）
- `(ルート)` 行：起点直下のファイル（フォルダに属さないファイル）は `(ルート)` 疑似行（深さ0）で表現する（Q28）。
- 収集：全ファイル（Q7=C・拡張子不問）。除外適用後（Q16=A'）。
- 出力：CSV既定（Q5=A）／HTML／Markdown。ファイル名は `asset_YYYYMMDD`＋同日 `_01` 連番（Q9=A・Q18=A）。
- 想定運用：実体（主にzip）は**リーフのタイトルフォルダ直下にのみ存在**する前提。

### 6.2 出力項目（11列）【確定: Q6=B/Q13=A'/Q15/Q20=A'/Q29=C】

| # | 列名 | 内容 | 備考 |
|---|---|---|---|
| 1 | 保管フォルダ | 起点からの相対パス（`\` 区切り）。`(ルート)` は起点直下を示す | 主キー。ソート既定＝相対パス昇順（Q14=A） |
| 2 | フォルダ名 | パスの末尾コンポーネント | 同名タイトルの検索・重複確認用（Q29-2） |
| 3 | 深さ | `(ルート)`=0、起点直下=1 | 階層フィルタ用（Q29-2） |
| 4 | ファイル数(直下) | そのフォルダ直下の実ファイル数（除外適用後） | 空フォルダは `0`（Q15=A） |
| 5 | サイズ(直下)byte | 直下ファイルの合計バイト（数値） | **ExcelのSUMはこの列**（Q39=A） |
| 6 | サイズ(直下)表示 | human readable（例 `1.2 GB`） | 可読性用（Q39=A） |
| 7 | ファイル数(配下) | 配下の再帰ファイル総数 | 分類フォルダの把握用（Q29-1） |
| 8 | サイズ(配下)byte | 配下の再帰合計バイト（数値） | 分類間の重さ比較用 |
| 9 | サイズ(配下)表示 | human readable | 可読性用 |
| 10 | 最新更新日時(配下最大) | 配下ファイルのmtime最大値（ローカル時刻 `YYYY-MM-DD HH:MM:SS`） | 0件は空欄（Q38=A） |
| 11 | 備考 | `読取エラーN件; リンクスキップN件` 形式（1セル内改行なし） | Q17=A・Q36=A・Q29-7 |

**行の読み方（Q29-16）**

- リーフ（実体あり）＝ `ファイル数(直下) == ファイル数(配下)` かつ `> 0`
- 分類フォルダ＝ `ファイル数(直下) == 0` かつ `ファイル数(配下) > 0`
- **前提違反**＝いずれにも該当しない（例：`直下1 / 配下3` ＝ 下位階層にも実体がある）

**合計行（末尾1行・Q20=A'・Q29-10）**

| 列 | 値 |
|---|---|
| 1 | `合計` |
| 4 | ファイル総数（ユニーク） |
| 5・6 | 総サイズ（ユニーク）: byte／表示 |
| 10 | 全体の最新更新日時 |
| 11 | `フォルダ数 N`（`(ルート)` を除く行数） |

- 列7〜9（配下系）は**二重計上のため空欄**とする。列4・5の合計は各フォルダ行の直下系の合計と一致する（Excelで検算可能）。

### 6.3 動作仕様【確定: Q8/Q14/Q16'/Q17/Q18/Q20'/Q22 ＋ Q30〜Q52】

- 除外：**部分木ごと枝刈り**（除外に一致したフォルダは行も子孫行も出さない・Q29-6）。判定は `mytools_common/scan.py` の述語（名前リスト／ドット始まり／HIDDEN属性／`--exclude-pattern`）を asset が参照する（Q30=A）。
- 除外名：repack既定（`.DS_Store`/`Thumbs.db`/`desktop.ini`/`.git` 等）＋**OSシステム項目**（`$RECYCLE.BIN`/`System Volume Information`/`pagefile.sys`/`hiberfil.sys`/`swapfile.sys`）を asset 用リストとして保持する（Q31=A）。repack側は変更しない（Q11=A）。
- リンク：ディレクトリリンク（ジャンクション/シンボリックリンク）は**追跡せずスキップ**し、行も出さない。ログに記録し、親行の備考に `リンクスキップN件` として集約する。訪問済み集合で循環を防止する（Q29-7・Q45=A）。
- 読取エラー：当該フォルダの統計値は**空欄**とし、備考に `読取エラーN件` を記録して継続する。終了コード2に寄与する（Q17=A・Q36=A）。**親の配下値は「取得できた範囲」の集計であり不完全**である旨をログに明記する（Q29-16）。
- 出力の作り方：一時ファイル（`asset_YYYYMMDD.csv.tmp` 等）へ逐次書き込みし、**完了時に `os.replace` で最終名へ**切り替える。中断（Ctrl+C／GUI中止）時は最終名のファイルを残さない（Q29-8・Q47=A）。
- 進捗：**ファイル走査数ベース**で更新する（フォルダ数は事前に不明なため）。メモリは訪問中の1ディレクトリ分のみ（Q46=A）。
- 行数：上限は設けない。100万行超はWARNを出す（Q29-8）。
- 出力名：`asset_YYYYMMDD`＋同日は `_01` 連番。`--output` は**フォルダ**指定で、ファイルパスや拡張子付きの指定はエラー（exit 1）（Q18=A・Q33=B）。
- ソート：`--sort name|size|mtime|files`＋`--order asc|desc`。`size|mtime|files` は**配下基準**（分類の重さ・新しさで並ぶ）。既定は `name/asc`（相対パスを区切りごとに比較・大小文字無視＝pre-order）。同値時は相対パス昇順、空値は末尾（Q14=A・Q29-3・Q29-12・Q50=A）。
- 合計行：末尾に1行出力する（6.2・Q20=A'）。
- 詳細一覧：`--detail` 指定時のみファイル単位の一覧を別出力する（6.7・Q26=A・Q27=A）。
- ハッシュ：`--with-hash` 指定時のみ SHA-256 を計算する（既定OFF・Q8=A）。詳細一覧に列を追加し、逐次計算＋件数表示とする。
- dry-run：走査と集計のみ行い**ファイル出力しない**。ログに要約（フォルダ数・ファイル総数・総サイズ・エラー件数）とサイズ上位N件を出す（Q35=A）。
- ログ：既定は出力フォルダ直下 `asset_YYYYMMDD-HHMMSS.log`。ヘッダ（版・入力・オプション）＋進捗＋要約を記録する（Q22=A・Q44=A）。ロガー名は `mytools.asset` とし repack（`mytools.repack`）と分離する（Q43=A）。
- 日本語・ロングパス対応は共通基盤（`mytools_common/paths.py`）に委譲。

### 6.5 asset CLIオプション（確定）【Q23=A・Q33=B・Q34改訂・Q35=A】

```text
python -m asset_tool --input IN --output OUT_DIR
  [--format csv|html|md] [--sort name|size|mtime|files] [--order asc|desc]
  [--recursive|--no-recursive] [--with-hash] [--detail]
  [--exclude-pattern REGEX] [--log-file PATH] [--log-level LEVEL]
  [--dry-run] [--config PATH]
```

| オプション | 既定 | 説明 |
|---|---|---|
| `--input` / `--output` | 必須 | 起点フォルダ／出力フォルダ（`--output` は**フォルダ**・Q33=B） |
| `--format` | `csv` | `csv` / `html` / `md`（Q5=A） |
| `--sort` / `--order` | `name` / `asc` | `name`・`size`・`mtime`・`files`（size等は**配下基準**・Q29-12）。同値時は相対パス昇順、空値は末尾（Q50=A） |
| `--recursive` | ON | ON=全階層（Q29=C）／OFF=起点直下のみ（旧Q19=A） |
| `--with-hash` | OFF | SHA-256を詳細一覧に追加（Q8=A） |
| `--detail` | OFF | ファイル単位の一覧を別出力（`asset_YYYYMMDD_detail.csv`・Q26/Q27） |
| `--exclude-pattern` | なし | 除外正規表現。一致したフォルダは**部分木ごと枝刈り**（Q29-6） |
| `--log-file` | 出力フォルダ直下 `asset_YYYYMMDD-HHMMSS.log` | ログ出力先（Q44=A） |
| `--log-level` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR`（repackと同一） |
| `--dry-run` | OFF | 走査と集計のみ・ファイル出力なし（Q35=A） |
| `--config` | なし | TOML設定（`[asset]` セクション・8章） |

- 出力名は常に `asset_YYYYMMDD`＋同日 `_01` 連番（Q18=A）。`--output` にファイルパスや拡張子付きの値を渡すとエラー（exit 1）。
- 終了コードは 0 / 2 / 1 / 130（6.3）。

### 6.6 出力形式の規約【確定: Q37〜Q42】

- **CSV**：UTF-8 **BOM付き**／CRLF／カンマ区切り／ヘッダ行あり／`csv` モジュール（QUOTE_MINIMAL）。値内の区切り・引用符・改行は `csv` が自動エスケープする（Q37=A）。
- **日時**：ローカル時刻の `YYYY-MM-DD HH:MM:SS`（Q38=A）。
- **サイズ**：byte列（数値）＋表示列（human readable）の2列を、直下系・配下系それぞれに持つ（Q39=A）。
- **空値**：空文字とする（`0` と区別する。読取エラー時も空欄・Q40=A・Q29-16）。
- **合計行**：CSV / HTML / Markdown いずれも末尾1行（6.2・Q41=A）。
- **HTML**：CSS埋め込みの自己完結（`result_*.html` と同じ流儀）。日本語フォント指定あり。ソート用JSは入れない。
- **Markdown**：GFMテーブル（Q42=A）。
- 3形式とも**同一の行セット・同一のソート順**で出力する（Q29-11）。

### 6.7 詳細一覧（`--detail`）【確定: Q26=A・Q27=A】

- 出力先：`asset_YYYYMMDD_detail.csv`（同日は `_01` 連番）。集約一覧と同時に出力する。
- 列：`相対パス` / `サイズ` / `更新日時` / `SHA-256`（`--with-hash` 時のみ） / `備考`。
- 用途：`--with-hash` と組み合わせて**同一タイトルの重複検出の材料**とする（重複検出機能そのものは非目的・1.3）。
- CSV規約は 6.6 と同じ（UTF-8 BOM／CRLF）。
